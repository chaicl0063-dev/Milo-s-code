## 3. 共同产品主线

核心体验：用户已经在陌生街区，看见一个地方，点一下，导游开始解释，并允许继续追问。

能力层次：
- 第一层“看懂这里”：地图选点、拍照识别、讲解、追问。
- 第二层“继续探索”：附近值得看的地方、短时路线、下一站。
- 第三层“旅行便利与记录”：翻译、收藏、离线内容、旅行日记。

官网优先说服用户体验第一层；应用顺势引出第二层。第三层在需要时出现，不在首次使用时挤占核心入口。
独自旅行是核心画像，两三人同行也适用；对外可用“按自己的节奏探索”，无需把独行写成使用门槛。

## 5. Claude 开发任务

### C01 · 功能状态总账（优先 P0，待核对）

逐项核对：地点讲解、随手问、拍照识别、翻译、路线、旅行者观点、主题漫步、日记、离线、账号。
每项记录：实现状态 / 用户开放状态 / 商业状态 / 入口 / 验证方式。
重点解决 PRODUCT-BRIEF 3.3“路线为未开放 Plus”与 4.4“已实现路线”的口径。
实现了、开放测试、已对公众开放、未来收费不是同一个状态。无用户数据库或只有邮箱登记时，不得把邮箱登记描述为完整账号系统。
验收：官网、应用与产品文档对同一能力的描述一致。

### C02 · 可到访地点筛选（P0，待实施）

把实体地点与百科背景资料分开：建筑、广场、公园、寺庙、店铺等可进入附近推荐；历史政权、事件、人物、机构历史用于讲解背景；行政区与城市用于区域介绍。
筛选逻辑基于实体类型、地点性质及可用证据，避免只按名称关键词误删真实遗址。无法判断的条目退出默认推荐，保留资料检索价值。
同步应用于地图、列表、路线候选；处理重复条目和粗略坐标带来的误导距离。
无真实定位时明确显示示例位置或当前浏览区域，不让用户误以为已定位到本人。
验收：已知异常条目不再作为独立可到访站点出现；实体遗址仍可正常出现；路线候选同样干净。

### C03 · 最短讲解路径（P0，待实施）

保留地点卡直达讲解。详情页顺序优先：地点图片与名称 → 推荐/介绍短句 → 听讲解与追问入口 → 到这里/地图入口 → 可展开详情与来源。
坐标保留在详细信息中，首要信息用地址、距离等用户能理解的内容；无可靠步行计算时不编造时间。
讲解的等待、准备音频、手动开始播放、失败重试必须有可理解状态；重试不丢地点。
首次引导尽量轻；官网带入的导游、语言和示例上下文不要被无故重置。
“三秒”先作为内部目标：测量点击听讲解到首句有信息量的音频，区分缓存/首次生成/失败重试；未验证前不作无条件官网保证。
验收：用户不必读完长文即可开讲；静音/暂停与追问可发现；错误可恢复。

### C04 · Guide 页按场景组织（P1，待实施）

保留 Around / Guide / Me。Guide 以当前探索为中心，而不是未上线功能目录。
主要场景：What’s this place? / What’s worth seeing nearby? / I have an hour.
拍照翻译保留明确工具入口；餐饮待数据就绪再加入；未上线预告降低层级。
从地点进入时直接解释该地点；从 Around 进入时继承浏览区域/选中地点；没有上下文才让用户选位置或示例；有路线时优先继续路线。
一小时场景：有位置则使用已有时间默认值、按需确认兴趣；无位置先选区域。不要重复询问已知信息。
按钮以可理解为先：营销可以写情境，操作可以使用准确功能名。
验收：每个场景都到达明确结果；不能使用的能力在点击前可识别。

### C05 · 路线的可执行性（P1，待核对及修补）

复用已有 2—7 站生成与地图联动。优先做好“一小时附近步行”，再扩展半天/一天。
- 步行模式默认不插入乘车；需交通时明确让用户选择；不为凑站数牺牲地点质量。
- 总时长应包含行走、停留和合理缓冲。
- 核对距离是直线还是道路距离；入口、绕路、跨河等影响可到达性。
- 虚线若仅连接站点，应标为顺序示意，不能冒充真实导航路径。
- 地图、路线栏、地点卡与讲解共享站点名称、编号、当前选择。
- 返回地图保留缩放、选中地点和路线；支持跳过站点后保持状态一致。
验收：至少提供一条实际可复核的路线记录，说明时长、交通方式、站点与地图关系；记录无法验证部分。

### C06 · 导游事实与现场表达（P1，待实施）

区别事实、传说、建议；不让 Mia/Milo 用无依据的“我记得”“我常来”伪造亲历。
没有可靠朝向时，不直接说“你左手边”；可改为“面对正门时左侧”或先确认位置。
人格体现在语气、节奏、重点，不在虚构身份。
讲解先短后长，给相关追问；来源可访问。避免为固定字数或故事性增加没有依据的细节。
验收：选取若干地点检查生成结果与出处；低信息场景不强行编故事。

### C07 · 餐饮与人群承诺（P2，待实施）

先接入并验证实体咖啡馆/餐馆，再实现按条件选择；“当地人常去”“更好吃”需要额外依据。
缺少营业与客流数据时不声称现在营业、无需排队、一定安静。
官网当前超前的餐饮/避开人群演示需改为真实可兑现的表达，或明确标注未来概念。
验收：存在地点、符合条件、推荐依据分别清楚；不将 OSM 类别本身当作质量评价。

### C08 · 未开放功能与商业表达（P1，待实施）

建议修改原“Paid feature”：未开放时用 Coming soon，辅以 Planned for Plus；已有可购买能力才用付费标签。
允许点击预览并由导游简短解释，但不要让几张主要卡都通往“还不能用”。
Free 随手问与 Plus 路线的区别优先体现为结构化、可保存、可调整、地图连续执行的体验，而非禁止用户自然地问行程。
不在本轮制定价格；“永久免费”等承诺与实际计划核对。
验收：用户在点击前知道当前能否使用，不误以为付钱即可解锁未完成能力。

## 6. 官网交互改版（Claude 实现，Codex 评审与图片）

### W01 · 核心演示：同一地点，从看见到听懂（P1）

首屏情境按钮保留页内演示，不强制跳应用。第一版优先展示现有可用能力。
推荐演示选一个真实地点贯穿：地点照片 → 地图选点 → 导游简短讲解 → 一个追问 → 继续探索。
明确“Interactive demo / Sample conversation”；预写内容不可伪装为实时 AI 响应。
场景切换同步更改照片、地点名、地图选中点、讲解及入口上下文，而不只换文字气泡。
默认静态内容可完整阅读；用户操作后才播放声音；提供重播、暂停与停止。不以自动长篇打字阻挡阅读。
地图、路线与聊天 UI 应复用真实产品组件或数据结构，不让生图生成伪截图来充当交互。
验收：鼠标、键盘、触屏均可切换；示例可完整读完；未加载音频时文字仍可用。

### W02 · Mia / Milo 试听比较（P1）

使用同一地点、同一主题的短片段试听，便于比较讲述风格；显示时长、播放状态和停止入口。
两段音频互斥播放。选择“和 Mia/Milo 开始”时将选择带入应用。
头像不等同于真人导游资质；生成的人物形象应以 AI 导游角色呈现。
验收：实际声音与应用一致；不依赖悬停；切换不会叠音。

### W03 · 短路线预览（P1，依赖 C01/C05）

时间/兴趣改变后，真实示例的站点顺序、地图标记和时长摘要同步更新；点击站点高亮地图并显示地点卡，支持还原。
尚未开放时明确“路线功能预览”，主入口指向预览或上线通知；不要使用会让人以为立即可规划的按钮。
示例所用路线需核验；预计算示例可优先于每次调用 AI，保证演示稳定，但必须如实标为示例。
验收：地图与列表对应；当前站清楚；任何路径都有返回/重置；不把装饰虚线当导航。

### W04 · 官网到应用的连续入口（P1）

主入口围绕“探索附近”；次入口为无需真实定位的示例体验。
传递明确的场景、地点、导游、语言；在应用侧校验并设置合理回退。不得在分享链接中夹带用户精确位置或私人会话。
位置只在执行相关任务时请求；拒绝后能选区域或继续示例。
Android 未开放时清楚写即将推出；不把下载作为 Web 体验前置条件。
验收：官网选择 Mia + 某地点后，应用不会无说明重置到另一位导游或无关地点。

### W05 · 页面互动原则与响应式（P1）

- 互动必须帮助用户理解产品，不增加装饰性任务。
- 不做滚动劫持、强制横向滚动、鼠标跟随特效、全屏自动视频或自动语音。
- 支持减少动态效果设置；动画关闭后信息与操作完整。
- 手机主动作紧跟价值说明，演示采用紧凑布局，不堆一串长胶囊和巨大手机空壳。
- 桌面可用地图与讲解并排，手机分层切换；共享同一状态，不要求机械地把手机纵向页面横排。
- 图片按宽度提供合适版本，非首屏内容按需加载；图片和演示预留空间，避免加载后跳动。
- 明确选中、加载、无结果、失败、重试和演示结束状态；不让颜色成为唯一提示。
- 第一版不增加城市货架；全球覆盖与一个城市演示可同时成立。

推荐页面顺序：价值与互动示例 → 真实地点完整体验 → 当前可用的少量场景 → 导游试听 → 来源与使用条件 → 开始体验及明确标注的未来能力。

useNarrator 的 fetchAudioUrl 回调目前只检查 playing/paused，没有本轮请求编号；GuidePanel 的事件仍转发到当前 timerRef。旧音频请求若在新轮已开始时返回，可能覆盖新音频并计入新轮。请 Claude 用“旧 TTS 延迟→停止/新请求→旧响应返回”验证，并在音频回调/事件侧绑定轮次、拒绝过期结果。计时器独立单元测试不能覆盖此异步连接问题。无需重写指标模块。
