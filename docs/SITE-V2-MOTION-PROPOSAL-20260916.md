# 官网 V2 动效方向建议

日期：2026-09-16
状态：建议稿，供 Milo 决定方向；不是 Claude 的执行指令。此次未修改页面代码。
范围：现有 /site-v2 官网的动效，不新增独立演示页。

## 1. 推荐方向

采用「轻显现 + 明确交互反馈 + 真实播放状态」。保留 B 样张的连续构图、紧凑横带和阅读顺序，让页面在进入、滚动、点击时有轻微响应。

动效结束后的画面应与最终静态版一致。动效不能用来掩盖版面问题；此前 F01–F04 仍是静态验收事项，目前不因讨论动效而自动视为通过。

上一轮验收中“不增加动效”是当时控制修正范围的建议；用户现已提出动效需求，本文件开启独立的动效设计讨论。它不改变静态版面的验收标准。

## 2. 推荐效果与边界

下表数值是本次建议值，不是已批准参数。后续执行清单应直接引用最终确定的数值，不再并列多套范围。

| 位置 | 建议效果 | 触发与结束 | 保持不动的内容 |
|---|---|---|---|
| Hero | 主产品卡从80%不透明度轻显现至100%，300ms；只在桌面首次呈现做一次 | 页面首次可交互时触发，无额外延迟；结束后保持正常卡片 | 标题、按钮、照片、图钉与元数据从首帧正常显示；没有整体开场动画 |
| Moment / SeeHear / Guides | 每段产品展示区整体从80%至100%不透明度，300ms；不逐项排队 | 首次进入视口时一次；滚回不重播 | 标题与说明常显；图片和图上标记归于同组，不分别移动 |
| 所有真实按钮与链接 | 鼠标悬停时颜色在150ms内过渡；按钮按下时内部视觉轻缩至98%，松开恢复 | 只响应真实悬停或按压；点击即时生效，不等动画结束 | 点击区域、周围排版与卡片位置不变；普通信息卡不添加假悬停反馈 |
| Hero / SeeHear / Guides 试听 | 仅实际播放时，已有波形位置出现轻微起伏；暂停后冻结，结束或失败恢复静态 | 跟随现有音频状态；切换导游时旧实例立即停止动态反馈 | 不自动播放；不新增人物说话动画；不把波形当作精确音频频谱或播放进度 |
| 页内导航 | 点击 How it works / Walks / Guides 等已有锚点时平滑定位 | 由点击触发；用户滚轮或触摸可以中断 | 不接管正常滚动，不吸附整屏，不新增吸顶导航 |
| Explore / CTA / Footer / Plus | 保持静态呈现；其中真实按钮沿用统一反馈 | Plus原有展开与成功/失败反馈保留，不另设计开合动画 | 地图点位、路线、人物与收尾横幅不做循环装饰动画 |

手机：不做Hero及段落显现，正文和产品卡直接显示；保留真实按压反馈、播放反馈与锚点定位。桌面有鼠标才有hover；手机不模拟悬停。

静态默认完整可读；脚本未运行或出错时也不得隐藏卡片。显现只用于增强，不将正文置为透明，也不以“滚到了才加载内容”实现。

## 3. 音频状态必须讲清楚

现有 useScriptedSpeech 提供 idle / loading / playing / paused / done / error；当前可见接口并未提供连续的已播放秒数。后续不要凭计时器制造从0到100%的进度。

- idle：静态波形、播放入口。
- loading：显示准备中文字；不提前起伏，不假装已经发声。
- playing：真实开始播放后波形起伏，按钮为暂停。
- paused：波形冻结，按钮可恢复；不继续跑“进度”。
- done：回到静态波形，可重播。
- error：静态波形与重试反馈；不持续显示播放态。
- 切换实例：旧实例音频与视觉状态同步复位。视觉不得另建一套独立计时状态。

波形起伏仅表达“正在播放”，不是逐帧对应声音振幅；无需为此次动效增加音频分析系统。保留真实句序信息，但不把句序比例标为精确时长进度。

## 4. 本轮明确不采用的效果

- 照片视差、鼠标跟随、卡片3D倾斜、持续漂浮：容易破坏连续构图和照片标记对应关系。
- 地图自动画线、流动虚线、移动光点、定位点持续呼吸：当前是示例站序，容易暗示导航、移动或实时定位。
- 识别扫描线、假打字、自动轮播问答：当前网页没有现场识别或现场生成，不用动画制造这种印象。
- 大标题逐字出现、整屏滚动锁定、连续入场延迟：干扰快速理解产品和点击体验。

这里“地图静态”不限制地图区域内真实按钮的统一交互反馈；“手机无入场”不限制用户主动播放后的真实状态反馈。

## 5. 特殊状态与验收方式

系统开启减少动态效果时：关闭显现、按压缩放、波形起伏和平滑定位；保留即时颜色/焦点反馈及文字播放状态。音频仍由用户主动操作，不因视觉设置取消功能。

装饰性动态在页面不可见或组件离开视口后停止；重新可见时根据当前真实播放状态恢复。停止装饰动画不等于自动暂停音频，音频行为维持现有逻辑。

静态截图只能验证最终构图，不能证明动效通过。执行轮应提交短录屏，覆盖首次进入、上下滚动、点击播放、暂停/恢复、跨模块切换和手机按压；减少动态效果模式另作核对。具体触发阈值、重播生命周期、动画曲线、文件范围、测试步骤与通过条件在方向确定后统一写入执行清单。

## 6. 后续执行清单如何避免歧义

方向确定后，仅生成一份正式执行清单，每项固定为：编号 → 元素 → 触发条件 → 起止状态 → 时长/曲线 → 重播规则 → 手机差异 → 减少动态效果差异 → 验证步骤 → 通过条件。

文件顶部写清批准状态、依赖的静态版本，以及覆盖本建议的哪些内容；不再以多份文档共同猜测参数。没有列入的元素维持静态，不让执行者自行补充“高级感”。

实施顺序建议：先收口静态F01–F04，再接入统一按钮与播放反馈，最后补桌面轻显现；复核后交付。当前只讨论方向，不要求Claude据本稿提前开工。
