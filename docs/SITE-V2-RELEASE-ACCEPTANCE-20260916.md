## 1. 状态与放行规则

每项只使用以下状态：
- PASS：已按步骤检查，有本轮证据。
- FIXED：曾失败，已修正并复测通过；同时保留问题及新证据。
- FAIL：未满足通过条件，必须先解决或按下述规则移除非必要能力。
- BLOCKED：环境、账号或设备等限制导致无法检查；不能写成通过。
- N/A：确实不适用，写明原因，不用于隐藏失败。

下列问题阻止发布：页面打不开、正式入口错误/循环跳转、主要CTA无法进入应用、主要内容缺失或严重遮挡、自动发声/多路试听同时播放、播放状态与实际持续矛盾、提交失败却显示成功、暴露敏感配置、核心资源加载失败、没有可执行的回退方案。

非阻塞项：不影响阅读操作的细微像素差、已登记且本轮未恶化的既有警告。列清具体影响，不笼统写“已知问题”；Claude不为此无限润色。

### 正式入口必须核实，不能猜

本轮读取的代码事实：`/site-v2`为预览，metadata设index:false/follow:false；`proxy.ts`按SITE_HOSTS把官网根路径重写到`/site`；NEXT_PUBLIC_APP_URL缺省为`/`。因此：

- 实施发布时先核对实际线上架构和部署权限，不把DEPLOYMENT.md的示例域名/历史Beta项目当成已授权目标。
- 默认按现有架构让正式`/site`呈现已验收V2，保留隐私/条款；官网根路径分流按当前域名配置。若采用其他已授权入口，记录理由及实际映射。
- 官网与应用分域时，NEXT_PUBLIC_APP_URL应指向实际应用地址；验证主CTA不回到官网本身。记录实际最终URL，不仅检查配置非空。
- 正式官网的robots/meta与canonical（若设置）指向正式可公开入口；预览仍可noindex。不能把预览页的禁止收录无意带到正式页，也不能为此全站放开预览。
- 搜索可抓取设置属于检查，不保证搜索引擎立即收录。

## 6. 哪些问题交给GPT

Claude可自行处理：已明确范围内的CSS错位、断点缺陷、播放视觉状态复位、错误链接配置、缺图及测试脚本错误；修完复测并记录即可。

提交GPT复核：
- 常规修复后仍复现，或同一问题反复修坏其他尺寸。
- 原清单与实现出现无法同时满足的要求。
- 需要改结构、改地图表达、添删产品能力或扩大动效范围。
- 无法提供关键测试证据，或性能/浏览器差异无法判断是否可接受。

异常单统一包含：ID、候选版本/环境、预期结果、实际结果、最短复现步骤、截图或录屏、已尝试修复与结果、需要GPT判断的一件事。不要只转述“感觉不对”或提交一整页无定位日志。

GPT回复只给该项结论：修复后复测 / 允许明确降级 / 需Milo决定，并说明依据；不重新审已经通过且未改动的模块。
