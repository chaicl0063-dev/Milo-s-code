# 给 Claude：全站分屏、统一宽度、四卡居中与页内转场需求（v2）

日期：2026-09-16
状态：按Milo最新补充修订为v2，覆盖v1关于“仅首屏满屏、正文普通长页、禁止分屏吸附”的规定。供Claude实施与自检；GPT本轮未修改页面代码。

## 1. 用户目标与已确认含义

用户原意：首屏四个信息卡片字体溢出且不居中；首屏满铺页面；顶部导航进入其他内容；向下滚动出现过渡画面后自动进入详情。

用户已明确选择：**同一页面，导航和下滚定位到下方内容区，不切换网址。** 因此“详情页”在本文指现有官网正文，不是新路由，也不是应用内地点页。保留同一个页面路径；不新增导航历史项，地址栏无需变化。

完成效果：打开官网只看到完整首屏；四张卡片文字清楚、居中；点击导航直达对应段落；主动下滚经过一段短转场后自然进入正文第一段。桌面正文也按主要段落分屏展示，滚动停止后对齐当前屏；不再让两三个段落长期挤在同一视口。滚动过渡中可以短暂看见相邻屏，这是正常连续转场。

## 2. 与旧要求的关系——以本节消除冲突

- 本文覆盖此前按样张固定Hero高度/整体页长的要求：首屏高度以浏览器可视区域为准，B样张继续用于颜色、字体和构图关系，不再用于限定Hero的绝对高度。
- 本文更新原动效清单M-N1对应的页内导航行为，并新增一次性的首屏到正文转场。旧“不做位移入场”仍适用于卡片和段落元素；页面平滑滚动不是给所有元素新增位移动画。
- 桌面允许原生分屏滚动对齐，取代v1“禁止每屏吸附”；不使用全屏滚动插件，不逐次吞掉滚轮事件。首屏出口转场与分屏对齐使用同一滚动流程，禁止两个控制器同时驱动。地图依旧静态，已完成音频与按钮反馈保持。
- 当前目标是视觉满足上线。Plus持久化、邮箱、应用业务等功能验证纳入上线后；但导航是否能到对应段落、转场是否误触发、页面是否可滚动属于本轮视觉交互，必须本轮验证。
- 此前首屏视觉通过结论不覆盖本次新构图。本次需复核所有主要段落的屏高与宽度对齐；既有照片、文字、产品功能和地图插画不重做。旧的整页高度、紧凑横带验收结果不能直接证明新分屏布局通过。

## 3. H01：首屏满铺可视区域

### 3.1 桌面

- 首屏总高 = 顶部导航 + Hero内容区 + 必要的首屏署名，总体占浏览器内容可视区一屏；不要把Hero单独设成一屏后再叠加导航和署名，导致打开时就多出一截。
- 正常100%缩放、1440×900 / 1280×800 / 1920×1080下，首屏底边与视口底边相差不超过2个CSS像素；正文与转场区尚不露出。
- 背景全宽，内容使用第3.3节的全站统一容器。文字、信息格、建筑和主产品卡按同一首屏构图协调，不再混用窄中央内容区与贴屏边的另一套坐标。
- 不通过整体等比放大旧Hero或单纯拉高照片凑满屏。保留大标题、主次按钮、四个信息格和产品卡的层级，避免巨大空白。
- 照片保持比例裁切，不拉伸。高度或object-position变化后重新核对所有图钉、地点标签；图钉标的仍是塔，不落在天空或被裁掉的部位。
- 首屏底部提供静态向下提示“Scroll to explore”，本身可点击进入正文第一段；不做持续跳动箭头。

### 3.2 手机、矮屏及文字放大

- 以铺满屏幕为最低高度，而不是不论内容多少都强制裁成一屏。按导航实际高度和可见视口处理，避免地址栏伸缩造成内容跳动。
- 375×812 / 430×812优先让标题、主CTA、地名、播放按钮、Mia身份与完整第一句可见。四个信息格可以在首屏内容的后半部；不为塞下一屏缩成难读小字。
- 当手机/矮屏/200%文字放大确实放不下，允许Hero自然增高。**全部Hero内容结束后才是转场区**，不能滚动一屏就把尚未读完的四张卡片跳过去。
- 手机顶部使用可见的“菜单”按钮承载原有三个导航项，保留Open the app；不把导航永久隐藏而没有替代入口。菜单打开时不触发自动转场，选项操作后关闭并定位对应段落。

### 3.3 H05：所有内容屏统一宽度与屏高

本条是用户看过正文截图后的明确补充，不限于Hero。

**桌面≥1024的屏幕顺序**：Hero → Moment → See & Hear → Explore → Guides → 收尾（Start＋Plus＋Footer）。收尾合为一屏，不把页脚单独拉成空白满屏。内容超过一屏时按下述例外处理。

- 普通桌面尺寸下，每个内容屏至少占一个浏览器内容视口高；内容容器在屏内垂直居中，有一致的上下安全留白。不要只给旧短横带加一大片底部空白，应调整三栏/双卡在屏内的占比和间距，保持明确视觉中心。
- 停留在屏的对齐位置时，除必要的全站导航外，视口显示该屏内容；不同时露出上一屏尾巴与下一屏标题。滚动中的相邻屏交接可见，不要求像幻灯片一样硬切。
- 外层背景可铺满视口。Nav、Hero文字组、各屏标题、正文、卡片舞台、CTA和Footer统一使用同一内容容器：**可用宽度为视口宽度的90%，上限1800px，水平居中；手机固定左右20px。** 这是v2的新统一宽度，取代旧1440px max-width与独立5%屏边定位的混用。
- 每个屏的栏目内部比例可以不同，但标题起始线与整体内容边界一致。1440/1920宽下，各屏标题左边界差不超过2个CSS像素；不得以“地图背景全宽”解释地图标题偏到屏幕左边。
- Explore：插画完整放入同一内容舞台，保持4:1比例，不拉伸成屏幕比例，不以cover裁掉Start或Old market。标题和按钮仍放在插画左侧留白中，但坐标基于统一舞台而非屏幕；若该断点放不下，改为舞台内上下布局。屏高由外层段落承担，不靠把地图纵向拉长来撑满。
- Hero背景仍可延伸到视口边缘；真正有语义的主卡、信息格和图钉需与照片裁切及统一舞台共同复核，不能机械把整个背景缩成内容宽度。
- 桌面停滚后使用原生分屏对齐到各屏起点，导航定位同一个屏起点；不再按旧模式把标题滚到视口24px而留下上一屏尾部。标题的上方留白由屏内排版提供。
- 手机、200%文字放大、矮屏或任何内容超过一屏的状态：完整阅读优先，关闭强制分屏对齐，内容自然增高、普通滚动。不得固定高度裁切、缩小文字、在卡片内另造纵向滚动条来伪装“一屏”。手机仍共享宽度和左右边界，不要求每段机械占一屏。

## 4. H02：四个信息格无溢出、真正居中

范围只限Hero四格（示例位置、当前区域、附近地点、导游状态），不改主试听卡为同样结构。

- 推荐统一为**上方图标、下方主值、再下一行说明**，整组内容水平与垂直居中。每张卡相同宽度、同一行等高、相同内边距；不要保留左图标/右文字后仅对某一行text-center，造成视觉中心偏移。
- ≥1440宽：4列一行；1024–1439及手机：2×2。每组按容器真实可用宽度排列，不让文字撑破网格。手机卡片顺序仍为1位置→2区域→3附近→4导游。
- 主值桌面15px、手机14px；说明12px。先调整容器、行高和换行，不通过缩到更小字解决溢出。
- 示例经纬度明确两行，每行一个完整坐标，数字与N/E或中文方向作为可识别的一组，不随意从小数中间折断。短地名和短状态可自然换行。
- 不对关键信息使用省略号、隐藏溢出或固定高度裁切。最内侧文字距离卡边至少12px，卡片实际高度由内容决定。
- 绿色状态点与对应说明文字作为一组居中；图标、主值、说明不互相覆盖。
- 默认英文必须检查；用户截图显示中文，也须用相同浏览器翻译场景检查。该要求不等于新增完整中文国际化：不要擅自翻译品牌名或产品人名，也不要以“浏览器翻译”作为溢出的免责理由。

## 5. H03：导航与入口的唯一对应表

| 入口 | 目标 | 行为 |
|---|---|---|
| Logo | 首屏顶部 | 当前页面回顶 |
| How it works | 现有See & Hear（#see） | 直接定位；不先经过首屏出口动画 |
| Walks | 路线插画段（#explore） | 同上 |
| Guides | 导游段（#guides） | 同上 |
| Hero的See how it works | #see | 同上；手机也应有明确可用入口，可用紧凑文字链接 |
| Scroll to explore | 正文第一段Moment（#moment） | 与首屏出口相同目标，主动点击直接平滑定位 |
| Open the app / Try it where I am | 现有应用地址 | 保持原真实应用入口，不改成官网详情 |

- 桌面定位到目标屏外层起点，标题完整可见且不露相邻屏尾部；若导航固定，则可用屏高与定位偏移都扣除同一个实际导航高度，不能重复扣除。本轮不要求新增固定导航。手机普通滚动模式可保留标题上方24px间距。
- 导航用真实链接保留无JS退路；正常增强模式页内定位，不新增路由、不额外压入历史记录。直接访问带hash的旧链接仍能到对应段落，不能为了保持首屏而强制回顶。
- 键盘激活导航后目标标题/段落可获得程序化焦点，焦点样式不破坏布局；普通滚动不抢走焦点。

## 6. H04：首屏下滚转场，与全站分屏同一流程

- 保留“首屏下滚经过短过渡画面，进入Moment”的目标。过渡采用近白浅蓝底与一行“Discover a deeper layer”及静态向下箭头，无新图片、扫描或地图动效。
- **取消v1独立160/120px转场区和80%视口阈值的规定。** 转场成为首屏与Moment交接过程中的轻显现，不新增独立吸附屏、不额外占一屏，也不单独控制滚动。
- 桌面用户主动向下滚动，交接过程中短暂看到过渡提示（淡入180ms），随后分屏对齐到Moment。导航直达SeeHear/Explore/Guides时跳过这段提示，不强制先经过Moment。
- 每次完整加载只播放一次过渡提示，回顶后再下滚不重播；后续各屏按统一分屏规则切换，不重复添加转场文案。用户反向操作或Escape可以停止程序化导航，不能锁住滚轮或反复把用户拖回目标。
- 页面初次加载、刷新后恢复正文位置、旧hash深链接、点击试听、打开菜单，都不能误触发首屏过渡或强制回首屏。
- 手机及长内容回退模式：自然滚入Moment，提示可以轻显现，但不再强制自动定位跳过内容；点击导航/向下提示仍可定位。
- 减少动态效果：无过渡显现、无平滑定位，关闭强制分屏吸附，允许普通阅读；真实链接仍可即时到目标。无JS时保留完整普通长页，不以脚本未启动为由隐藏正文。
- 音频播放不由换屏逻辑重置或启动；沿用当前视觉离屏暂停动画、音频独立的规则。
