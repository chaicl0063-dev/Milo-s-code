## 3. 收口项：按此顺序处理

### C01｜修复首屏以下底色露出（必须；现象确认，原因待运行时复核）

现象：full-1440 在约 y=900 CSS px 后，大片背景从冷近白切成旧版米黄；手机在初始812 CSS px之后也出现同样变化。取样桌面空白区域后段为RGB(244,241,234)，对应全局 body 的 #f4f1ea。不是新的设计方向。

高度恰好等于初始视口，是关键线索。app/globals.css:41 把 html/body 设为100%高；app/layout.tsx:40 的 body 是纵向 flex；SiteV2Landing.tsx:20 的 .rr2 是 min-h-dvh 的可收缩子项。高度被压至视口而子内容溢出的可能性很高，需运行时确认，不能只据截图宣称原因已完全定位。

修法：
1. 正常滚动查看 #see、#guides，读取 .rr2 的实际高度、scrollHeight 和背景；区分真实页面问题与 captureBeyondViewport 的渲染差异。
2. 若 .rr2 高度只有视口，局部阻止该根节点 flex 收缩（如 shrink-0 或等效方式），让背景覆盖全部内容。
3. 不为官网修复全局 body 配色，避免影响应用与旧官网。
4. 同时用普通滚动视口图和完整页复验；不能只把拼接底色涂成冷白掩盖页面问题。

通过条件：整页背景一致，没有在812/900或分片边界处突然变色。

### C02｜让所有试听互斥（必须；代码缺少实例间互斥，尚未实测双声）

推荐最小处理：

Hero播放 → Hear Mia；Hero准备中 → Hear Milo；Guides播放 → Hero；播放中跨640px断点；离开页面。每条只允许一个输出，迟到请求不能恢复旧播放，隐藏控件不能成为唯一暂停入口。
