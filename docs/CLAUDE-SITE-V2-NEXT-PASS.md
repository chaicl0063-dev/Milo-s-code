## 2. 执行顺序

### A. 先修已明确的局部错误

1. Hero：Sample 说明不得被卡片盖住；固定巴黎坐标必须归属示例，不能显示成访客实时定位。
2. Moment：桌面地点标签不得被照片容器裁切；手机卡片不得覆盖坐标。窄屏优先正常布局，不靠 overflow 隐藏错误。
3. PlusNotify：读取 signup 的 JSON，只有明确 ok:true 且 stored:true 才进入已登记；stored:false、无效响应、非 2xx、网络失败都保留输入并给出可重试状态。使用模拟响应验证，不向真实名单发送测试邮箱。
4. Moment 的识别叙事需体现用户主动选点或拍照，不暗示导游自动知道用户正在看哪栋建筑。应用有拍照识别，不要误删真实能力。

### B. 然后仅做 Hero 静态样张

修改范围原则上为 Hero.tsx、必要的 ui.tsx 局部样式和 content.ts 的 Hero 数据；需要改共享样式时复核其影响。A 中的 Moment/PlusNotify 为必要例外。

手机布局建议：

## 3. 评审图与脚本要求

输出放 docs/screens/site-v2-next/，保留当前 docs/screens/site-v2 作为对照。至少提供：

- Hero：1280×800、1440×900、375×812。
- Hero 补查：360×812、430×812，以及 1024×800、1100×800（固定宽卡片的断点风险）。
- Moment：桌面与手机局部图，证明裁切/重叠已经消除。
- 完整页：1440 和 375 宽，确认共享样式未破坏其余段落。

脚本需要改进的地方：

1. 保持正常视口高度拍整页。现在把 viewport height 改成整页高度再截图，会改变依赖 vh/dvh 的布局；本轮不据此断言旧图已失真，但应避免后续动效/视口逻辑受干扰。
2. 明确等待字体就绪、图片加载与解码；记录实际失败资源，不只固定 sleep。
3. 输出 viewport、DPR、CSS scrollHeight、图像像素尺寸和拍摄时间；避免把 2 倍像素的图片高度写成页面高度。
4. 保留根节点宽度检查，但增加关键标签的边界、遮挡及可见性检查；overflow-x-clip 内部被切掉的内容不会可靠地反映为根节点溢出。
5. 对自定义 origin 的参数解析补一个小验证：现 outIdx=-1 时 i !== outIdx+1 会排除第一个位置参数，直接传 origin 可能被忽略而回退 localhost:3000。只修参数解析，不借机重写整套截图工具。
6. 全页截图要确认拍到了 Footer；达到高度上限时应报告截断，不能作为完整页交付。
