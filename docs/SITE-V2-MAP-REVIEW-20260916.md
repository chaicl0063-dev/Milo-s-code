## 3. 为什么改成曲线仍不好看

1. **真点位太挤。** 桌面1440×360舞台中1/2中心距约16.4px，无法同时放两个32px编号而不重叠。四个真实点仅横跨约133px，而地图右侧展示空间远大于它。样张则把节点沿横向连续展开。
2. **编号不在路径上。** 当前真实点是小圆点，1/2/3放在远处白卡里，再以同样蓝色实线牵回去。读者需要先区分路线虚线与标签引线，再推断编号归属；小图中尤其难读。
3. **弧线承担了本不该承担的避让。** 2→3控制点向西额外拉出9–10个百分点，试图避开起点，形成大回头弯。曲线变圆并没有让游览逻辑更自然。
4. **曲线尺度不统一。** 同一组100×100百分比控制偏移同时用于4:1桌面和1:1手机。相同偏移在两种宽高比下呈现完全不同的曲率，不能仅因使用贝塞尔曲线就宣称流畅。

## 4. 推荐方案：换适合展示的真实样例，再做曲线

**推荐保留真实地图、三站、一小时预算的产品范围，重新选择地理分布更适合横向展示的真实路线样例。** 不再把“必须保留当前这三个地点”作为约束。这是对前轮固定旧fixture的建议作出的明确修订，不是要求移动旧点位。

选择原则：
- 仍在巴黎，与全页城市语境一致；Explore可有独立示例起点，清楚标为sample，不冒充Hero地点到路线起点的实测连接。
- 使用应用真实输出，保存请求、响应、地点ID与坐标；选择三个有独立游览价值的停留点，避开“广场及其喷泉重复算两站”。
- 在固定起点条件下核对访问顺序与可达性，不为凑左到右而偷偷改序；优先选自然展开、无明显折返的候选。
- 在1440宽、约4:1底图预览中，真实点位的横向范围应足以支撑右侧构图；32px编号圆之间至少留12px净空。做不到就换候选或调整真实地图缩放裁切，不能移动单个地理点。
- 不预先承诺具体新地名或道路；本轮没有核验新路线，不能给Claude一组看似准确的虚构坐标。

这是小范围替换官网演示数据与地图图层，不要求顺带重构应用路线算法。若现有应用暂时产不出合适样例，先保留旧展示并报告原因，不编造“应用规划”结果，也不先制作一条假路线等以后补证据。

## 5. 曲线具体如何呈现

选好样例后统一采用以下表达，不混用两种路线定义：

**本轮采用“真实地点地图上的站序连接示意”，不是逐街步行导航。** 地图近处可见标题建议 `Sample walk · stop order`；详细说明保留。线可以适度弯曲，但不刻意描出一条绕楼、穿河的貌似真实走法。

- 一个Start标记，三个编号直接落在真实地点上，沿线一眼读到Start→1→2→3。每段可加一个小方向箭头，箭头为静态，数量不堆叠。
- 三段构成一条连续蓝色圆头虚线；接点处方向平顺，无额外回环、自交或为了避让卡片而画的大绕圈。
- 按实际地图宽高比的像素坐标计算控制点；桌面和手机分别校验。当前“同一个100×100坐标系加固定偏移”不继续沿用。
- 曲线只作轻弯。点位分布负责整体节奏，不靠巨大控制偏移制造S形。如果某段只有直线才清楚，允许该段接近直线，不要求每一段都弯。
- 卡片靠近各自编号，交错排布；空间不够先移动卡片或切换列表，不移动地理点。必要引线用细淡灰实线，和蓝色路线明确区分，尽量短。
- 保留现有蓝色3.5px主线与白色衬线作为初始值；先解决点位和编号关系，不继续通过加粗、加光晕掩盖问题。
- 底图继续浅化，文字卡可读。真实地图与点位保持同一投影，换样例后必须重新生成两版底图和全部点位。

如果希望表达“游客真的沿着这条线走”，那是另一项需求：先取得并核验步行道路几何，只圆润真实拐点，不能用任意贝塞尔弧线替代。这一项不混进当前站序示意实施。

## 6. 保留旧样例时的有限修补

若用户决定不换当前样例，只能改善清晰度，不能承诺得到样张那种横向铺展：取消西侧大弧，1/2采用近邻组合标注并保留原三站列表，压短引线、区分线色、加访问方向。组合标注不等于已经把两次停留合并为一次；若合并站数，须同步更改样例来源、站数、时长和文案。

此项是“不换样例”的备选，不与第4节推荐方案同时执行。
